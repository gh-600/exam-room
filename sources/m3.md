## Conflicts between the module and GitHub Docs (no questions built on these)

- **U3** · Module: A local MCP server is added like a remote one, with a local endpoint such as `http://localhost:3000`. · Docs: Local servers are normally started as a command over `stdio` (`type` `local` or `stdio` with `command` and `args`), not addressed by a localhost URL. (https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers)
- **U4** · Module: A custom agent file scopes files with `applyTo`, and its tools are named `read_file` and `search_files`. · Docs: `applyTo` belongs to `*.instructions.md` files, not to agent files; check tool names in the custom agents configuration reference. (https://docs.github.com/en/copilot/reference/custom-agents-configuration)
- **U4** · Module: The CI example runs `npx @github/copilot-cli` authenticated with `secrets.GITHUB_TOKEN`. · Docs: The package and authentication details differ; check the Copilot CLI docs before copying the example. (https://docs.github.com/en/copilot/how-tos/copilot-cli/install-copilot-cli)
- **U5** · Module: The agent "doesn't automatically create a pull request"; you decide whether to create one. · Docs: Unit 2 of the same module, and the cloud agent docs, describe the agent opening the pull request itself. What is certain: it can't merge, and review stays with a human. (https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent)
- **U5** · Module: The retry example loops three times with `&& break` and `sleep 5`. · Docs: As written, the step succeeds even when all three attempts fail, because the last command is `sleep`. A retry loop must exit non-zero after the final failure. (https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)
